# Routing and Dispatch OSS Reuse Audit

Date: 2026-09-19
Status: research only; no dependency, code, configuration, provider call, or final architecture decision was made.

## Scope and Boundary

本审计的目标是寻找能放在 `Codex parent -> HarnessMesh thin authority -> OSS -> provider/runtime` 链路中的现成组件。HarnessMesh 只能封存 invocation、授予最小权限、校验上游 identity evidence、记录 receipt，并把项目 Harness/acceptance 留给 parent；OSS 不得拥有任务编排、acceptance、预算决定或项目权限的最终解释权。

本轮重新 clone 了每个候选的当前 default-branch HEAD 到独立 `/tmp/hm-routing-research-20260919/`，阅读源码、许可证、测试与一手官方文档。GitHub REST 统计于 2026-09-19 获取；`open_issues_count` 不被当成 issue 数。activity 中的 issue/PR 是“created in window”，commits 是 GitHub commit listing 的 author-date window；它们是维护信号，不是质量证据。GitHub Search API 随后触发 rate limit，因此只采用已经成功返回的统计，不补猜数字。

`STATIC` 表示固定源码审阅；`UPSTREAM REPORT` 表示 issue/README/变更记录中的上游陈述；`NOT RUN` 表示没有执行该项目的测试。没有任何 live provider、付费调用、CLI session 或上游身份验证。本报告刷新并质疑了 `docs/baseline/research/global-cross-model-subagent-landscape.md`，但不把它当作本轮证据来源。

## Evidence That Changes the Reuse Picture

### `superagent-ai/gateway`: strongest functional gateway, blocked by license

这是目前最贴近“thin authority 下的 protocol gateway”的候选。它分别实现 Claude Messages 和 Codex Responses ingress，显式分类 `tools`、tool result、image、thinking、stream 与 cache control，并拒绝能力不足路由；[eligibility implementation](https://github.com/superagent-ai/gateway/blob/041b08a658ffd0ae587d7065ebb6f4d2ccfc1a18/src/classify.rs#L96-L120) 和 [mocked integration coverage](https://github.com/superagent-ai/gateway/blob/041b08a658ffd0ae587d7065ebb6f4d2ccfc1a18/tests/integration.rs#L215-L238) 说明这不是 README-only claim。

其 `model_map` 明确把 Claude pinned `claude-opus-*`/`claude-haiku-*` 分流到 `subagent`/`background` role，[config owner](https://github.com/superagent-ai/gateway/blob/041b08a658ffd0ae587d7065ebb6f4d2ccfc1a18/src/config.rs#L24-L40)，且测试覆盖了这些 alias 与 Codex unknown-model rejection。[test](https://github.com/superagent-ai/gateway/blob/041b08a658ffd0ae587d7065ebb6f4d2ccfc1a18/tests/integration.rs#L499-L538) 其 pre-stream-only fallback 也避免已经出现 tool/text 后悄然换模型，[attempt implementation](https://github.com/superagent-ai/gateway/blob/041b08a658ffd0ae587d7065ebb6f4d2ccfc1a18/src/http.rs#L459-L524) 和 [documented contract](https://github.com/superagent-ai/gateway/blob/041b08a658ffd0ae587d7065ebb6f4d2ccfc1a18/README.md#L321-L329)。

但是 pinned repository 根目录没有 `LICENSE`，`Cargo.toml` 也没有 license metadata。即使功能与测试值得持续关注，当前不能 `DIRECT`、`WRAP`、`VENDOR` 或 `FORK`。该结论是本轮静态许可证核查，不是对作者意图的推断；仅在 maintainer 明确添加适用开源许可证后，才重新审计其 transformer/stream modules 和第三方依赖。

### CCR: constrained compatibility sidecar, with independent identity observation

CCR 的 [Codex patch bridge](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/gateway/features/codex-patch-bridge.ts#L178-L230) 处理 call、result 与 conversation history，不能只 rename tool。它是实际 compatibility implementation，不能仅因完整 CCR 还有 routing/admin 功能就排除模块复用。

但 [Anthropic SSE rewrite](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/gateway/features/anthropic-response-model.ts#L74-L93) 会把 `message_start.message.model` 替换为 client-visible model。该字段因此不能成为 HarnessMesh 的 observed identity evidence。历史上 [#1564](https://github.com/musistudio/claude-code-router/issues/1564) 报告过 system tag 位置造成 silent wrong-model routing（`UPSTREAM REPORT`，本轮未复现）；当前 extraction 已改进，但 [unknown/unconfigured tag 的后续 route](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/gateway/claude-code-router-plugin.ts#L474-L497) 仍不等于 HM 的 sealed route failure semantics。

**可行的研究候选是 WRAP**：Claude Code → 固定版本 CCR sidecar → HM credential/egress/identity broker → 唯一 sealed provider endpoint。Codex 仍是 parent；CCR 不派发 worker、不选择任务、不持有项目 acceptance。HM broker 在 CCR 转换之前独立检查每次实际 outbound model/effort 和原始 upstream response；CCR 回传的 alias 只标为 compatibility presentation。

源码支持这个切点：[default config](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/config/default-config.ts) 有 `Router.fallback.mode="off"`、built-in rule switches、空 custom router/plugins/MCP 和 observability 开关；[providerBaseUrl](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/config/config.ts#L652-L654) 接受自定义 endpoint；[gateway bootstrap](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/gateway/core-runtime/gateway-bootstrap.ts) 有 child IPC startup/disconnect seam。配置开关不是 containment proof：sidecar 仍须只访问该 broker、无真实 provider key、无 host HOME/config、无项目写权限，且不能启动插件、account probes、MCP 或其他外连。Broker 独立拒绝任何额外 provider/model/unauthorized request，不信任 sidecar 声称已关闭 fallback。

`@claude-code-router/core` [package](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/package.json) 是 `private: true`，不是已证实的稳定独立 npm API；WRAP 应固定上游 distribution/build 与 Node >=22、transitive dependencies，不能假定直接安装该 private package。`requestLogs=false` 的默认配置仍有 `requestLogBodyCapture="all"`，必须显式关闭 body capture，并实测所有诊断路径不泄漏。当前尚未启动 CCR，以上是源码支持的 bounded composition hypothesis，**不是已 qualification**。

Kimi、GLM、MiniMax 有 provider presets，可作为 Claude compatibility 候选；但 [Kimi preset](https://github.com/musistudio/claude-code-router/blob/a034b0c51cdd1b5628bbff545821f5540d30c6c5/packages/core/src/providers/presets/kimi-coding/index.ts) 默认 `kimi-for-coding` / `K2.7 Code`、`api.kimi.com`，不是当前 HM 的 sealed K3 route。不能照抄 preset 就宣称 K3 合格。需要每个 runtime/provider/model/tool tuple 单独证据；如果受限启动、tool fidelity 或 broker 插入点不能通过 qualification，该 tuple 保持 blocked，不 silent fallback。

### `shinpr/sub-agents-skills`: reusable CLI builders and parsers, alternative executor seed

其清晰的 `AgentInvocation -> ProcessInvocation -> subprocess -> StreamProcessor -> AgentResponse` 分层位于 [builder](https://github.com/shinpr/sub-agents-skills/blob/84e1d4b311dd1f87b71687b62cb1d97744393b80/skills/sub-agents/scripts/_builder.py#L13-L42)、[executor](https://github.com/shinpr/sub-agents-skills/blob/84e1d4b311dd1f87b71687b62cb1d97744393b80/skills/sub-agents/scripts/_executor.py#L143-L163) 与 [stream parser](https://github.com/shinpr/sub-agents-skills/blob/84e1d4b311dd1f87b71687b62cb1d97744393b80/skills/sub-agents/scripts/_stream.py#L72-L206)。argv 是 closed CLI set，`shell=False`，并将 stdin 置为 `DEVNULL`，[spawn site](https://github.com/shinpr/sub-agents-skills/blob/84e1d4b311dd1f87b71687b62cb1d97744393b80/skills/sub-agents/scripts/_executor.py#L300-L331)。这是可评估 vendoring 的最小成熟 seam。

但 `build_final_response` 不保留 parsed model/session/usage；executor 只为 stdout 创建 reader，stderr 在 `communicate()` 才读，且只 kill direct child，[source](https://github.com/shinpr/sub-agents-skills/blob/84e1d4b311dd1f87b71687b62cb1d97744393b80/skills/sub-agents/scripts/_executor.py#L170-L276)。因此本轮不把其 output 当作 identity receipt，也不把 kill 当作 process-tree cancellation。Kimi/GLM 虽通过 Claude CLI profile 出现，但这是 transport configuration，不是 Kimi/GLM/K3 upstream identity 或 tool-loop conformance evidence；Gemini、Grok 与 native Kimi/GLM 的实际 session 均 **NOT RUN**。

### CodeRouter and `coderouter-plugin-agents`: useful process facts, wrong controller

`agent_cli` 的 [timeout path](https://github.com/zephel01/coderouter-plugin-agents/blob/b5797fd8457337831827b4322200b50d019e008a/src/coderouter_plugin_agents/adapter.py#L390-L422) 确实 kill process group，但 cancellation is not handled by that `generate` finally path. 更关键是 final `ChatResponse.model` 永远来自 configuration，[source](https://github.com/zephel01/coderouter-plugin-agents/blob/b5797fd8457337831827b4322200b50d019e008a/src/coderouter_plugin_agents/adapter.py#L1040-L1058)，而 prompt renderer 只保留 text content，[source](https://github.com/zephel01/coderouter-plugin-agents/blob/b5797fd8457337831827b4322200b50d019e008a/src/coderouter_plugin_agents/adapter.py#L1060-L1089)。它不能证明模型、freeform tools、structured outputs 或 MCP/tool transcript 被完整保留。任意 non-zero exit 可 retry，[source](https://github.com/zephel01/coderouter-plugin-agents/blob/b5797fd8457337831827b4322200b50d019e008a/src/coderouter_plugin_agents/adapter.py#L1190-L1197)，对有 side effect 的 CLI 不可作为 HM 默认策略。

`Code-Router/CodeRouter` 是不同项目；它拥有自己的 orchestration/judge/worktree flow，不能以名字相同误认为是 adapter library。二者都没有本轮 Kimi、GLM、Grok、Gemini live evidence。

### Mature alternatives: LiteLLM, ACP, and `acp-router`

LiteLLM 的官方文档确认它统一多 provider OpenAI-style call、router/fallback、proxy 与 MCP gateway，[official docs](https://docs.litellm.ai/docs/)。源码的 `Router` 位于 [router.py](https://github.com/BerriAI/litellm/blob/b8d837b2ef04da6953a93d136c69eb3980bcb34d/litellm/router.py#L712)，其 fallback headers helper 位于 [router_utils](https://github.com/BerriAI/litellm/blob/b8d837b2ef04da6953a93d136c69eb3980bcb34d/litellm/router_utils/add_retry_fallback_headers.py#L248-L273)。这是成熟 provider API gateway；但它默认的 value proposition 包含 retry/fallback、normalization、keys/administration/MCP gateway，不是一个无权威的 coding-agent CLI supervisor。若 HM 将来需要纯 HTTP provider translation，可考虑将其作为**独立受限外部 service**，但不可让其 route decision、fallback 或 response model 取代 sealed route / identity receipt。

ACP 官方定义的是 editor/agent interoperability；local agent 用 JSON-RPC over stdio，remote transport 仍在演进，[official introduction](https://agentclientprotocol.com/get-started/introduction)。稳定 wire version 依赖 `initialize` negotiated `protocolVersion` 与 capabilities，而不是 SDK/schema release，[source](https://github.com/agentclientprotocol/agent-client-protocol/blob/8587a6d198b695b4ec156a5c128d6f8ff6dab485/README.md#L19-L29)。它是 native runtime adapter 的良好 `WRAP` target，不是 model routing/identity evidence implementation。

`puzige/acp-router` 是最明确 ACP controller example：它把 mode/permission/default agent/parent env 变成自己的 configuration，[tool schema](https://github.com/puzige/acp-router/blob/e5e49a9ff1b5a1e454d4cd57bcaab69bf04a8881/src/server.ts#L76-L120)，并默认 `bypassPermissions` 与 environment inheritance，[storage defaults](https://github.com/puzige/acp-router/blob/e5e49a9ff1b5a1e454d4cd57bcaab69bf04a8881/src/storage.ts#L175-L192)。它的 worktree/session/job persistence、SIGTERM recovery 和 MCP surface 说明其已拥有 controller role，故不能被 HM 直接装入。也没有本轮 ACP runtime E2E。

### `duolahypercho/codex-router`: reference test assets, no direct gateway adoption

该项目的 custom/freeform evidence 值得复用：它明确区分 `apply_patch` 的 native custom-tool contract 和其他 freeform tools，[source](https://github.com/duolahypercho/codex-router/blob/5e1b49e6e3fea1ada57f0e7fa6ca7612e9d17300/src/deepseek-responses.mjs#L39-L52)。它还把 billed compatibility test 显式置于 `--live --yes`，并覆盖 text、stream、tool call、stateless tool result、compaction，[source](https://github.com/duolahypercho/codex-router/blob/5e1b49e6e3fea1ada57f0e7fa6ca7612e9d17300/src/compatibility-test.mjs#L289-L338)。这是 HM future qualification 的优秀 `REFERENCE_ONLY` 测试思路；但它自身是一个大型 local router/OAuth/config control plane，且其 provider-specific Kimi endpoint/config 不构成 HM 的 runtime identity evidence。

## LOC Estimate and Method

这些是候选比较估算，不是已批准 implementation plan。物理文件与责任切片大小不同；估计复用量需在实际选定 exports 后复核，误差至少 ±35%。库或 sidecar 通过 API 调用，不把整个 dependency tree 计为“复用了多少自研 LOC”。下列 alternatives 不相加；commodity report 的 AnyIO/HTTPX/ACP wrapper estimates 是同一责任的替代口径。

| Slice | Estimated upstream reuse | Adapter production / tests LOC | Decision boundary |
| --- | --- | --- | --- |
| shinpr builder/parser selected functions | 450–550 candidate source LOC before excluding credential/permission defaults | 70–110 / 120–200 | Optional VENDOR; no executor or credential loader import. Actual retained subset may be smaller. |
| shinpr executor fork alternative | 180–230 relevant upstream LOC | 260–400 / 300–450 | Not selected over AnyIO; estimate includes fixes, not a second CUSTOM supervisor. |
| CCR compatibility sidecar | pinned core/gateway dependency, no copied LOC claim | 150–300 / 250–450 | Does not include HTTPX egress guard or provider policy; no fork assumed without a demonstrated interface blocker. |
| LiteLLM sidecar alternative | pinned external proxy dependency | 140–240 / 200–350 | Alternative provider translation, not a second stacked gateway by default. |
| HM identity evidence acceptance policy | upstream mechanisms reused separately | 140–220 policy / 180–300 tests | CUSTOM candidate only for evidence associations and acceptance predicates; detailed burden below and in synthesis. |

`CUSTOM` candidate 只涵盖 HM 的 **evidence acceptance policy**，不是 HTTP、JSON、SSE、日志或 persistence plumbing。`DIRECT`：CCR rewritten model 与 CodeRouter configured model 不满足 sealed-request/per-wire association。`WRAP`：可以并且应复用这些机制，但 wrapper 必须新增 HM 的 seal、provider observation provenance 与 freshness predicates；这个新增 policy 才是 CUSTOM。`VENDOR`：上述 attribution functions 不包含这些 predicates，复制代码不会消除其自研部分。`FORK`：给 gateway 增加 HM qualification/parent authority 会把项目 policy 绑在高频变化的 gateway 内，而外部 broker 已能提供正确观察切点；无需为此 fork transport。Exact blockers 是本报告所链接的 model rewrite/config attribution 与缺少 HM seal association，不是“无法证明远端权重”。可信等级可以是 authenticated endpoint declaration；不得声称 cryptographic remote-model attestation。预计 policy 140–220 production / 180–300 tests LOC；HM 维护者拥有 predicates、升级兼容和 breaking-change responsibility，upstream 仍维护机制。隔离薄 policy 比 fork gateway 的长期风险低；如以后发现同等 policy library，应重新比较，不能把该候选永久豁免于 reuse-first。

## Research Outcome (Not a Final Design)

1. **Do not default to self-building a router.** AnyIO/HTTPX WRAP 是更低层的成熟机制候选；shinpr builder/parser 可选 VENDOR，executor FORK 只是替代方案，不是默认。
2. **Keep `superagent-ai/gateway` under watch.** Its code and test boundary are the best functional match for Claude/Codex routing, aliasing and tool-aware fallback, but absence of a declared license is an exact stop condition for executable reuse.
3. **Use ACP as a transport wrapper, not a dispatch owner.** Its negotiated capability model is mature and matches the thin-authority boundary better than `acp-router`.
4. **Use CCR as a bounded compatibility candidate.** Prefer WRAP of pinned gateway code with independent HM egress/identity policy. Codex-router remains REFERENCE_ONLY for native custom-tool fixtures. Neither owns observed identity or parent acceptance.
5. **LiteLLM is credible only as an externally bounded provider API service.** It should not gain parent acceptance, sealed route, or fallback authority; it does not replace native CLI or ACP process handling.

Open evidence remains deliberately explicit: current upstream license decision for superagent gateway; actual installed CLI behavior; Kimi/GLM/Grok/Gemini credential and identity evidence; real tool/MCP transcript preservation; cancellation of descendant processes; and release-to-release breaking-change compatibility. Those require a future bounded qualification round, not inference from this research artifact.
